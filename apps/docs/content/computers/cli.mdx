Eight commands drive a machine. Every flag below is what `parse()` accepts in the
command's source, and `husk help <command>` lists the same ones.

Seven global flags work everywhere: `--json`, `-q/--quiet`, `--no-color`, `--color`,
`--debug`, `-y/--yes` and `-h/--help`. `-y/--yes` being global is why `husk rm --yes`
works even though `rm` declares no `yes` option of its own.

Exit codes are an API and are frozen: `0` ok, `1` error, `2` usage, `130` interrupted.
`husk exec` is the one deliberate exception — it exits with the child's own code.

## husk up

```bash
husk up [name] [flags]
```

Creates a computer. With no name, Husk generates one. Nothing runs inside it until you
`exec`.

| Flag | Values |
| --- | --- |
| `--provider <p>` | `docker`, `podman`, `local`, `ssh`, `fly`. Default: best available |
| `--flavor <f>` | `base`, `python`, `node`, `full`. Default: `base` |
| `--memory <size>` | `2g`, `512m`, or a plain number of MB |
| `--cpus <n>` | A positive number |
| `--network <mode>` | `none`, `egress`, `full`. Default: no policy, which allows everything but internal addresses, as `full` does |
| `--packages <p,..>` | Install these at create time. Comma-separated or repeatable |
| `--persist` | Keep the filesystem across restarts |
| `--env K=V` | Set a variable inside the machine. Repeatable |
| `--idle-timeout <sec>` | Destroy after this long idle, while the shared Husk runs. A positive number. Default: never |
| `--json` | Print the computer record instead of the summary |

`egress` allows only the hosts on an allow list, and `husk up` has no flag for one.
Packages from `--packages` are built into an image of the computer's own on Docker and
Podman, tried with `uv`, `pip` and `npm` on `local`, and refused on `ssh` and `fly`.

`--memory` accepts `2g`, `2gb`, `512m`, `512mb` or a bare number of MB, and rejects
anything else with a usage error rather than guessing.

```bash
husk up
husk up scratch --provider local
husk up builder --flavor python --memory 2g --network full
husk up api --env PORT=8000 --idle-timeout 3600
```

## husk ps

```bash
husk ps [--all] [--json]
```

Tab-separated, so `cut` works:

<Terminal>
{`$ husk ps
name	id	provider	state	workdir	age
scratch	cmp_5j8svxeqer9p	local	running	/work	51s`}
</Terminal>

```bash
husk ps --json | jq -r '.[].name'
husk ps | cut -f1,4
```

`--all` (or `-a`) includes stopped machines.

## husk exec

```bash
husk exec <name|id> -- <command...>
```

Everything after `--` belongs to the command, flags included. That boundary is preserved
before parsing, so `husk exec box -- ls -la` passes `-la` to `ls` rather than rejecting
it as an unknown Husk flag.

| Flag | What it does |
| --- | --- |
| `--cwd <path>` | Working directory inside the machine. Default `/work` |
| `--timeout <sec>` | Kill the process tree after this long. Default 120 |
| `--env K=V` | Set a variable for this command. Repeatable |
| `--stdin <text>` | Text piped to the command on stdin |
| `--json` | Buffer and print the full `ExecResult` instead of streaming |

stdout and stderr stream live, and Husk exits with the command's own exit code:

```bash
husk exec scratch -- uname -sr
husk exec scratch -- 'echo hi > /work/a.txt; cat /work/a.txt'
husk exec scratch -- test -f /work/a.txt && echo present
husk exec scratch --json -- ls /work | jq .exitCode
```

A timed-out command exits `124`, which is what `timeout(1)` uses, and `ExecResult.timedOut`
is `true` so a caller does not have to key off the number.

## husk shell

```bash
husk shell <name|id> [--cwd <path>]
```

A readline loop, **not a pty**. Each line is a separate `exec`, so Husk tracks `cd` for
you, but full-screen programs — `vim`, `top`, `less` — and anything that checks `isatty`
will not work. Leave with `exit`, `quit`, or Ctrl-D. `--cwd` sets the directory it
starts in.

## husk cp

```bash
husk cp <src> <dst>
```

Either side may be `name:/path`. Directories are copied recursively, except on Fly,
which copies one file at a time, of at most 32 MB.

```bash
husk cp ./report.csv scratch:/work/report.csv
husk cp scratch:/work/out.json ./out.json
husk cp ./src scratch:/work/src
```

A single-character prefix before the colon is always a Windows drive letter, never a
computer name — no computer name is one character — so `husk cp C:\data\x.csv
scratch:/work/` does what a Windows user expects. A path starting `//` after the colon is
treated as a URL scheme separator and left alone, so `http://…` does not parse as a
computer called `http`.

On `local` and `ssh` the computer's side goes through the path jail, as the file tools
do, so copying out of `/etc` is refused; on `ssh`, a directory's links are followed, as
`scp -r` follows them. On Docker, Podman and Fly the copy can reach any path inside the
computer, which is the computer's own filesystem, not this machine's. The local side is
yours, and is not checked.

## husk rm

```bash
husk rm <name|id> [--all] [--erase] [--yes] [--force]
```

<Danger>
Destroys the machine and its filesystem. There is no undo. On Docker and Podman a chat's
computer, or a bot's with `computer.persist: true`, keeps its files and browser logins
for its next computer, so for those it means "stop for now"; `--erase` takes them too, as
the console's Delete does.
Husk asks first unless `--yes` or `--force` is given, and refuses on a non-interactive
stdin without one. `--json` does not skip the question.
</Danger>

| Flag | What it does |
| --- | --- |
| `--all` | Destroy every computer |
| `--erase` | Also erase the files and browser logins a chat's or a persistent bot's computer keeps |
| `--yes`, `-y` | Skip the confirmation (global flag) |
| `--force`, `-f` | Skip the confirmation, and with `--all` destroy computers used in the last minute too |

## husk stop and husk start

```bash
husk stop <name|id>
husk start <name|id>
```

No flags beyond the globals. `stop` keeps the filesystem; `rm` does not, except what a
chat's or a persistent bot's computer keeps for its next one.

## Errors

One red line and one dim hint. Never a stack trace unless you ask:

<Terminal>
{`$ husk exec ghost -- ls
error no computer named "ghost"
hint:  there are no computers yet — create one with \`husk up\``}
</Terminal>

Every error is a `HuskError` carrying a machine-readable `code` and a one-line `hint`
that says what to do next. `--debug` prints the stack.

## Piping

`--json` is on every read command and is the only thing on stdout when set. Spinners,
progress, warnings and the one-time orientation block all go to stderr, so this is safe:

```bash
husk doctor --json 2>/dev/null | jq -r .selection.isolated
```

Colour follows `NO_COLOR`, `FORCE_COLOR`, `TERM=dumb` and `--no-color`, and each stream
keeps it only when it is a terminal: `husk doctor > report.txt` carries none.

Ctrl-C aborts in-flight work rather than killing the process, so a run stops between
steps and a machine is never left half-created. A second Ctrl-C leaves immediately.
Writing to a closed pipe — `husk ps | head -1` — is normal and exits `0`.
