Husk comes two ways. Pick the one that fits; neither needs the other, and neither has an
account step.

| | The desktop extension | The npm packages |
| --- | --- | --- |
| For | Claude Desktop | the `husk` CLI, MCP clients such as Claude Code, Cursor and Zed, and bots |
| Needs | Claude Desktop, which brings its own Node | Node 20.10 or newer |
| Gives you | workspaces, and computer tools when you turn them on | every tool, and the CLI |
| Start with | [Your first workspace](/start/workspaces) | [Quickstart](/start/quickstart) |

## The desktop extension

Download `husk-0.2.0.mcpb` from the
[Husk 0.2.0 public preview](https://github.com/Hotragn/husk/releases/tag/preview-0.2.0),
and install it in Claude Desktop through **Settings → Extensions → Advanced settings →
Install Extension**. It needs no terminal, no Docker and no Node of your own.
[Your first workspace](/start/workspaces) walks through the first task, and through what
the preview does not do yet.

## The npm packages

| | |
| --- | --- |
| Node | 20.10 or newer (`engines.node: ">=20.10"`) |
| Platform | Linux, macOS, Windows |
| Everything else | optional |

There are no native modules anywhere in the tree, which is a build-contract rule rather
than an accident: `better-sqlite3` and `node-pty` are both banned. A Windows machine
with no C++ toolchain gets a clean `npm install`.

<NotYet>
These pages describe 0.2.0, and npm still has 0.1.4. Until 0.2.0 is published, run the
CLI from a checkout of the repository: `npm ci && npm run build`, then
`node packages/cli/dist/bin.js <command>`.
</NotYet>

### Run it without installing

```bash
npx -y @husk-ai/cli doctor
```

Good for a first look. Every invocation pays npm's resolution cost, so it is not what
you want for day-to-day use.

### Install the CLI globally

```bash
npm install -g @husk-ai/cli
husk doctor
```

The binary is `husk`. `husk --help` costs about 16 ms on top of Node's own startup,
because every command sits behind a dynamic `import()` and the help text loads none of
them.

### Connect your chat apps

```bash
husk setup
```

It asks where your chats' computers should run, adds Husk to the chat apps you pick from
the ones it finds, backing up each file it changes, and starts the shared Husk every chat
goes through. `husk setup --remove` takes it out again, and
[the CLI reference](/reference/cli#husk-setup) has its flags. `husk onboard` is the
guided tour instead: five steps, from what this machine can do to the command to run next.

### Install the MCP server only

If all you want is a computer inside Claude Code, you do not need the CLI at all:

```bash
claude mcp add husk -- npx -y @husk-ai/mcp
```

See [MCP](/mcp).

## The packages

`@husk-ai/cli` depends on the first five and treats the last three as optional — `husk mcp`,
`husk serve` and the SDK load lazily and fail with an actionable error if they are
absent.

| Package | What it is |
| --- | --- |
| `@husk-ai/core` | Contracts, the `husk.yaml` schema, `paths()`, `redact()`. Depends on nothing but zod. |
| `@husk-ai/runtime` | Computer providers: docker, podman, local, ssh, fly. |
| `@husk-ai/models` | The model router: 11 providers, no vendor SDKs. |
| `@husk-ai/sessions` | Transcript importers and the distiller. |
| `@husk-ai/agent` | The tool-calling loop and the built-in tools. |
| `@husk-ai/mcp` | The MCP server. Optional. |
| `@husk-ai/server` | Control plane and bot host. Optional. |
| `@husk-ai/sdk` | Typed client for the control plane. Optional. |
| `@husk-ai/cli` | The `husk` binary. |

Four more come in through those: `@husk-ai/browser`, the Chromium driver;
`@husk-ai/workspaces`, the saved workspaces; `@husk-ai/adapters`, the Discord, Slack and
Telegram front ends; and `@husk-ai/console-assets`, the console.

## Optional pieces, and what each one buys

Nothing below is required. Each one changes what `husk doctor` reports.

**Docker or Podman** gives you a kernel boundary instead of process guardrails. This is
the one that matters if an agent will read anything you did not write. Start Docker
Desktop, or install Podman and run `podman machine init`.

**Ollama** gives you a model with no API key and no network egress:

```bash
ollama pull qwen2.5:7b
```

That is about 4.7 GB, after which `husk run` works offline.

**An API key** gives you a frontier model. Husk reads these from the environment, and
from `~/.husk/.env` for any the environment does not set. It never writes them:

```bash
export ANTHROPIC_API_KEY=...   # or OPENAI_API_KEY, GOOGLE_API_KEY, GROQ_API_KEY, …
```

The full list of variables Husk reads is in [Model providers](/models).

## What lands on disk

All state lives under one directory so you can back it up in one move and delete it in
one move. `$HUSK_HOME` overrides the location; otherwise it is `~/.husk`.

```
~/.husk/
  config.json       global settings
  .env              API keys, if you keep them here: Husk reads this file, never writes it
  husks/            registered husks, one directory each
  computers/        computer metadata (not filesystems) + bindings.json
  workspaces/       saved workspaces (ws_*), and the local provider's working directories (cmp_*)
  runs/             run results and event traces
  transcripts/      imported transcripts, cached
  data/             the audit log: one file per computer, a line per tool call
  cache/            downloaded assets, snapshot tarballs
  daemon.json       the shared Husk's address and token
  daemon.log        the shared Husk's log
  jobs.json         the job host's address and token, while a bot has a trigger
  remote/           remote access: its signing key, the owner's passkey, the apps signed in
  .oriented         the marker that stops the welcome block reprinting
```

On WSL, the `local` provider keeps a computer's working directory inside the distro, in
its own `~/.husk/workspaces`.

Every directory is created with mode `0700`, and `daemon.json` and `jobs.json` are
readable only by you. Husk never writes your API keys here. The credentials it does keep
are its own: the shared Husk's and the job host's tokens, and remote access's keys.

## Uninstall

```bash
husk rm --all --erase --force   # every computer, and the files any of them keeps
npm uninstall -g @husk-ai/cli
rm -rf ~/.husk
```

`--erase` takes the files and browser logins that a chat's computer, or a bot's with
`computer.persist: true`, keeps on Docker and Podman. `--force` goes ahead when a computer was used in the last minute,
where `--yes` refuses.

<Danger>
Removing `~/.husk` deletes every saved workspace, with its sources and results. Export
the ones you want to keep first.
</Danger>

Removing `~/.husk` resets Husk completely, including the one-time orientation block. It
does not remove Docker containers created by a previous version of the CLI; `husk ps
--all` lists them while the CLI is still installed. To remove the desktop extension,
uninstall it from Claude Desktop's extension settings; its workspaces are in the same
`~/.husk`.
